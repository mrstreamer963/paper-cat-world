# Этап 1. Геометрическое ядро

## Цель и результат

Создать чистое детерминированное JavaScript-ядро вложенной двумерной сцены. По завершении сущности можно создавать, перемещать между поверхностями с сохранением мировой позы, поднимать по слою и скрывать вместе с родительской ветвью. Циклическое вложение и некорректные числа отклоняются до изменения состояния.

Запускаемый результат — `npm run demo:core`: сценарий создаёт стол, два бумажных контейнера и фигурку, последовательно вкладывает их, печатает мировую трансформацию фигурки и показывает ожидаемый отказ при попытке вложить внешний контейнер в собственного потомка.

## Зависимости и границы

Это первый этап. Он создаёт `package.json`, структуру `src/core/`, `tests/core/` и headless-скрипт демо.

В этап не входят Vite, PixiJS, DOM, Pointer Events, рисование, специализированные коты/листы/тетради, сохранение и UI. Контейнеры в демо — обычные сущности с принадлежащими им тестовыми поверхностями.

## Модель и публичный API

`createWorld(config)` создаёт новое состояние с корневой поверхностью стола. Минимальная форма данных:

```js
{
  rules: { geometryEpsilon, minScale, maxScale },
  table: { width, height, surfaceId },
  entities: {
    [id]: {
      id,
      kind: "paper",
      surfaceId,
      transform: { x, y, rotation, scale },
      zIndex
    }
  },
  surfaces: {
    [id]: {
      id,
      kind: "table" | "generic",
      hostEntityId: null | string,
      transform: { x, y, rotation, scale },
      placementArea: [{ x, y }],
      localVisibility: "visible" | "hidden"
    }
  }
}
```

`createWorld(config)` проверяет и нормализует доменные параметры в `world.rules`; дальнейшие этапы расширяют этот объект, не меняя сигнатуру команд. `placementArea` — простой замкнутый многоугольник без повторения первой точки; для стола это прямоугольник против часовой стрелки. Корневая поверхность имеет единичную трансформацию и `hostEntityId: null`. Остальные поверхности принадлежат ровно одной сущности. Мировая матрица сущности равна `worldMatrix(parentSurface) × localMatrix(entity)`; мировая матрица поверхности-владения — `worldMatrix(hostEntity) × localMatrix(surface)`.

На этапе экспортируются:

```js
createWorld(config)
applyCommand(world, command)
validateWorld(world)
getEntityWorldTransform(world, entityId)
getSurfaceWorldMatrix(world, surfaceId)
isEntityVisible(world, entityId)
```

Последние три функции — read-only запросы: они не возвращают изменяемые внутренние объекты. Публичные команды:

- `createEntity`: получает `entity` и необязательный массив принадлежащих ему `surfaces`; все ID переданы вызывающей стороной.
- `moveEntity`: получает `entityId`, `targetSurfaceId`, локальную `transform` и `zPolicy: "preserve" | "front"` (по умолчанию `preserve`).
- `moveEntityInWorld`: получает `entityId`, `targetSurfaceId`, желаемую мировую трансформацию и ту же `zPolicy`; ядро само вычисляет локальную позу и при `front` — следующий `zIndex` целевой поверхности.
- `setEntityTransform`: меняет позу на текущей поверхности.
- `bringEntityToFront`: ставит `zIndex` на единицу выше текущего максимума целевой поверхности.
- `setSurfaceVisibility`: служебная команда для generic-поверхностей; на этапе 5 её заменят доменные команды для листов и тетрадей.

`validateWorld` возвращает `{ ok: true }` либо `{ ok: false, errors: [{ code, path, details }] }` и собирает все обнаруженные ошибки, а не останавливается на первой.

## Последовательность реализации

1. Инициализировать npm-проект с `type: module`, Vitest и общими scripts из индекса. Настроить раздельные каталоги модели, геометрии, команд и публичный `src/core/index.js`.
2. Реализовать в геометрии создание/умножение/инверсию affine-матриц и преобразование точки. Декомпозиция поддерживает только равномерный положительный масштаб; недопустимая или вырожденная матрица возвращает доменную ошибку.
3. Реализовать площадь полигона, проверку конечности координат и `pointInPolygon`, причём точка на границе считается находящейся внутри.
4. Реализовать создание мира и полную валидацию ссылок, уникальности, размещения, полигонов и чередующегося графа `surface → entity → owned surface`.
5. Реализовать запросы мировых матриц итеративным проходом с защитой от уже посещённых ID. Рекурсивная видимость равна видимости поверхности и всей цепочки её владельцев.
6. Реализовать command dispatcher и атомарные обработчики. Копировать только изменившиеся записи и словари; исходный `world` не менять.
7. Для reparenting вычислять `inverse(targetSurfaceWorld) × desiredEntityWorld`, затем декомпозировать результат. До применения проверять существование и видимость цели, попадание anchor point в `placementArea` и отсутствие цикла.
8. Добавить headless-демо с фиксированными ID и assert-проверками, чтобы оно завершалось ненулевым кодом при регрессии.

## Ошибки и крайние случаи

Стабильные коды этого этапа: `DUPLICATE_ID`, `ENTITY_NOT_FOUND`, `SURFACE_NOT_FOUND`, `INVALID_REFERENCE`, `INVALID_NUMBER`, `INVALID_TRANSFORM`, `INVALID_POLYGON`, `OUTSIDE_PLACEMENT_AREA`, `TARGET_NOT_VISIBLE`, `CYCLE_DETECTED`, `UNKNOWN_COMMAND`.

- Перемещение в ту же поверхность допустимо и обновляет трансформацию.
- Попытка положить сущность на поверхность, которой владеет она сама или любой её потомок, возвращает `CYCLE_DETECTED`.
- Скрытая поверхность продолжает хранить содержимое, но не принимает `moveEntity` и делает всю ветвь невидимой.
- Нулевой/отрицательный масштаб, `NaN`, `Infinity`, отсутствующие ссылки и вырожденные полигоны не попадают в новое состояние.
- `bringEntityToFront` работает только среди соседей на одной поверхности. Равные исходные `zIndex` разрешаются стабильной сортировкой по ID, чтобы результат был детерминирован.
- Глубокая вложенность проверяется итеративно, чтобы цепочка из сотен контейнеров не переполняла стек.

## Автоматические тесты

Запуск: `npm test`.

- Матрицы: identity, композиция translate/rotate/scale, инверсия и round-trip точки.
- `local → world → new local` сохраняет мировые координаты, угол и масштаб в пределах общей epsilon-константы.
- `pointInPolygon`: внутренняя, внешняя и граничная точки; отклонение вырожденного полигона.
- Создание сущности с дочерней поверхностью и вычисление мировой позы через несколько уровней.
- Перемещение между поверхностями через локальную и мировую команды.
- Рекурсивная видимость при скрытии поверхности на каждом уровне.
- Отклонение прямого и непрямого цикла без изменения ссылки на `world`.
- Все невалидные ссылки и числовые значения дают ожидаемые коды.
- Две одинаковые команды над структурно одинаковыми мирами дают глубоко равные результаты и события.
- Команда не изменяет замороженный входной объект.

## Ручное демо

1. Выполнить `npm install`, затем `npm test`.
2. Выполнить `npm run demo:core`.
3. Убедиться, что фигурка после двух reparenting остаётся в той же мировой позе.
4. Убедиться, что попытка циклического вложения напечатана как ожидаемый `CYCLE_DETECTED`, а последующая `validateWorld` успешна.
