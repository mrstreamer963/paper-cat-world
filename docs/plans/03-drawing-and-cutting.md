# Этап 3. Рисование и вырезание

## Цель и результат

Добавить сфокусированный редактор бумаги, в котором пользователь рисует кистью и ластиком, отменяет действия и обводит замкнутый контур ножницами. Подтверждённый контур создаёт универсальную бумажную деталь, которую можно перетаскивать на столе как сущность предыдущих этапов.

Запускаемый результат — браузерный сценарий «чистая бумага → рисунок → контур → отдельная деталь» с сохранением штрихов как источника истины и RenderTexture только как кэша.

## Зависимости и границы

Этап начинается после полного checklist [этапа 2](02-table-interaction.md). Он расширяет ядро данными рисунка, cutout-сущностью и историей команд, а приложение — отдельным режимом редактора.

Не входят заливка, фигуры, текст, слои, импорт изображений, распознавание смысла рисунка, редактирование геометрии готового контура и специализированные шаблоны кота/одежды.

## Модель, команды и история

В мир добавляется словарь `drawings`. Документ рисунка имеет форму:

```js
{
  id,
  width,
  height,
  background: "transparent" | string,
  strokes: [{
    id,
    tool: "brush" | "eraser",
    color,
    width,
    points: [{ x, y, pressure }]
  }]
}
```

Pressure нормализуется в диапазон `0..1`; если устройство его не даёт, приложение передаёт `0.5`. Ядро хранит исходные точки, не сглаженную рендерную геометрию. Cutout-сущность расширяет общую сущность полями `kind: "cutout"`, `drawingId`, `contour` и `anchor`; её локальная точка `(0, 0)` совпадает с anchor.

Новые команды:

- `createDrawing` и `deleteDrawing`, причём удаление запрещено, пока на документ есть ссылки;
- `addStroke` и `removeStroke`; весь stroke с заранее созданным ID коммитится одной командой на `pointerup`;
- `createCutout`: получает ID сущности и нового drawing, исходный `drawingId`, проверенный/сырой contour, целевую поверхность и мировую позицию anchor;
- `deleteEntity`: удаляет обычную сущность и принадлежащие ей поверхности только при отсутствии размещённого содержимого; связанные неиспользуемые cutout-drawings удаляются той же атомарной командой.

История находится в core, но вне `world`:

```js
createHistory(world, { limit })
applyHistoryCommand(history, command)
applyHistoryGroup(history, commands)
undo(history)
redo(history)
```

Каждая успешная команда создаёт обратную операцию с минимальным снимком изменённых записей. `applyHistoryGroup` последовательно проверяет команды на временном состоянии и либо применяет их все одной записью, либо возвращает исходные world/history при первом отказе; inverse-команды выполняются в обратном порядке. Новая команда очищает redo-stack; отказ не меняет историю. Pointer preview и незаконченный stroke в историю не попадают. Drag уже является одной `moveEntityInWorld` с `zPolicy: "front"`. Лимит по умолчанию задаётся конфигом и применяется удалением самых старых записей.

## Редактор и геометрия ножниц

- Редактор открывается поверх стола как сфокусированный canvas с собственной камерой. Один pointer рисует, два pointer всегда pan/zoom редактора; камера стола в это время заблокирована.
- Toolbar содержит brush, eraser, scissors, цвет, размер, undo, redo, подтверждение и выход. Все действия доступны touch и клавиатуре; hover не используется.
- Приложение собирает точки активного stroke во временный preview, переводит их в координаты документа и коммитит один `addStroke` на окончание жеста.
- Renderer сглаживает линию для показа, но итог всегда воспроизводим из сохранённых точек. После commit соответствующая RenderTexture инвалидируется и перестраивается один раз.
- Scissors собирают полилинию. Если конец находится в пределах конфигурируемого порога от начала, ядро заменяет его точным началом; иначе возвращает `CONTOUR_NOT_CLOSED`.
- Контур отклоняется, если имеет меньше трёх различных вершин, самопересечение, не конечные точки или площадь меньше `minCutoutArea` из config.
- Anchor — центроид площади контура. Новый drawing и contour переводятся так, чтобы anchor стал `(0, 0)`. В новый drawing копируются strokes, чьи расширенные по толщине AABB пересекаются с AABB контура; Pixi mask окончательно скрывает части вне полигона.
- Новая деталь появляется так, чтобы мировое положение центроида совпало с положением рисунка на рабочей бумаге либо с явно переданной точкой появления рядом с редактором.

## Последовательность реализации

1. Расширить модель/валидацию словарём drawings, ссылками cutout и проверками stroke/contour.
2. Реализовать команды рисунка и cutout с детерминированным копированием данных и структурированными событиями `drawingChanged`, `entityCreated`, `entityDeleted`.
3. Добавить геометрию полилиний: расстояния, AABB, signed area/centroid, пересечение сегментов и проверку простого полигона.
4. Добавить core-history, обратные операции и группировку команд. Перевести drag этапа 2 на `applyHistoryCommand` без изменения поведения.
5. Реализовать DOM toolbar и контроллер editor-mode с отдельной pointer state machine и камерой холста.
6. Реализовать stroke preview, commit на `pointerup`, нормализацию pressure и обработку cancel без частичного stroke.
7. Создать кэш drawing texture по ключу `drawingId + revision`; revision увеличивается только успешной командой изменения рисунка. Освобождать заменённые RenderTexture.
8. Реализовать scissors preview, сообщения валидации, создание cutout и Pixi mask.
9. Подключить undo/redo кнопками и стандартными сочетаниями с учётом фокуса; undo не должен отменять camera/UI-state.

## Ошибки и крайние случаи

Новые коды: `DRAWING_NOT_FOUND`, `DRAWING_IN_USE`, `INVALID_STROKE`, `STROKE_NOT_FOUND`, `CONTOUR_NOT_CLOSED`, `CONTOUR_SELF_INTERSECTS`, `CONTOUR_TOO_SMALL`, `INVALID_CONTOUR`, `HISTORY_EMPTY`.

- Tap без движения создаёт короткий круглый stroke с одной точкой, если размер кисти валиден.
- `pointercancel` удаляет только preview и не создаёт запись истории.
- Eraser на прозрачном месте всё равно сохраняется как stroke и корректно участвует в undo/redo.
- Повторяющиеся соседние точки scissors удаляются до геометрической проверки.
- Самокасание несоседних сегментов считается самопересечением; общая вершина соседних сегментов допустима.
- Неудачный cut не закрывает редактор и сохраняет рисунок, чтобы пользователь исправил контур.
- Undo создания cutout удаляет сущность и созданный drawing; redo восстанавливает те же ID и данные.
- Удаление контейнера с содержимым отклоняется, а не удаляет дерево неявно.

## Автоматические тесты

Vitest (`npm test`):

- валидация brush/eraser strokes, pressure и невалидных чисел;
- add/remove stroke и неизменяемость исходного drawing;
- авто-замыкание в пределах порога и отказ вне порога;
- площадь, центроид, самопересечение и граничные контуры;
- нормализация contour вокруг anchor и выбор пересекающихся strokes;
- create/delete cutout сохраняют ссылки и дают ожидаемые события;
- undo/redo stroke, cutout, move и атомарной группы команд;
- отказ внутри history-группы откатывает временные результаты и не создаёт запись;
- новая команда очищает redo, отказ оставляет оба stack без изменений;
- drawing revision инвалидирует только нужный texture cache key.

Playwright (`npm run test:e2e`):

- brush и eraser мышью в Chromium;
- рисование touch/stylus-подобным pointer и pinch редактора в mobile-webkit;
- undo/redo кнопками после нескольких strokes;
- незамкнутый и самопересекающийся contour показывают понятную ошибку;
- валидный contour создаёт masked detail, которую можно переместить на стол;
- выход из редактора и pointercancel не оставляют незаконченный stroke.

## Ручное демо

1. Выполнить `npm test`, `npm run test:e2e` и `npm run build`.
2. Открыть чистую рабочую бумагу и нарисовать разноцветный предмет с участком, стёртым ластиком.
3. Отменить и повторить последние штрихи; убедиться, что меняется только рисунок.
4. Провести явно незамкнутый contour и увидеть отказ без потери рисунка.
5. Обвести предмет корректно, получить отдельную masked detail и переместить её на другую поверхность.
6. Отменить и повторить создание детали, проверив стабильность её положения и вида.

## Checklist готовности

- [ ] Список strokes — единственный источник истины рисунка.
- [ ] Рендерные кэши можно полностью удалить и восстановить из world.
- [ ] Один завершённый stroke и один drag создают по одной записи истории.
- [ ] Невалидный contour не создаёт частичных сущностей/drawings.
- [ ] Редактор не конфликтует с камерой стола на touch.
- [ ] Полный путь «рисунок → contour → movable cutout» проходит в Chromium и mobile-webkit.
