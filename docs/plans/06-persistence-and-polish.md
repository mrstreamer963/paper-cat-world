# Этап 6. Сохранение и доводка PoC

## Цель и результат

Завершить PoC самодостаточным версионированным сохранением, безопасным восстановлением, мобильной компоновкой и оптимизацией реальной сцены. После JSON round-trip должны воспроизводиться все восемь проверяемых сценариев дизайн-документа.

Запускаемый результат — production build без сервера/аккаунта: пользователь создаёт мир, экспортирует `.json`, начинает другой мир, импортирует файл и получает визуально и структурно тот же стол. Перезагрузка страницы предлагает восстановить последнее валидное локальное автосохранение.

## Зависимости и границы

Этап начинается после полного checklist [этапа 5](05-sheets-and-notebooks.md). Он стабилизирует созданные контракты, но не добавляет новые игровые механики.

Не входят облако, аккаунты, мультиплеер, обмен творениями, бинарные assets, импорт изображений, сохранение history/кэшей/незавершённых жестов и гарантии совместимости форматов до `schemaVersion: 1`.

## Формат и API сохранения

Публичный API core дополняется:

```js
serializeWorld(world, metadata = {})
loadWorld(input, config)
```

`serializeWorld` сначала вызывает `validateWorld`, затем возвращает plain object:

```js
{
  format: "paper-cat-world",
  schemaVersion: 1,
  metadata: { title },
  world: {
    table,
    entities,
    surfaces,
    drawings
  }
}
```

Порядок ключей словарей при сериализации сортируется по ID, чтобы одинаковые миры давали стабильный JSON. В envelope не попадают history, selection, camera, editor state, pointer state, animations, RenderTexture и другие кэши. Шаблоны не дублируются: сохраняется `templateId`, а `loadWorld` проверяет его наличие в переданном config.

`loadWorld` принимает JSON-строку или plain object и возвращает `{ ok: true, world, metadata, warnings }` либо `{ ok: false, error: { code, message, details } }`. Порядок загрузки:

1. безопасный parse без изменения текущего приложения;
2. поверхностная проверка `format` и целочисленной версии;
3. последовательные чистые миграции `N → N + 1` до текущей версии;
4. создание in-memory `world.rules` из актуального config приложения и полная структурная/доменная `validateWorld`;
5. возврат нового world только при полном успехе.

Для версии выше поддерживаемой возвращается отказ. Реестр миграций создаётся пустым для v1 с тестовой fixture устаревшей версии в unit-тесте каркаса, но вымышленные pre-v1 production-форматы не поддерживаются.

## Файловый импорт и локальное восстановление

- Экспорт создаёт UTF-8 JSON с двухпробельным форматированием и скачивает файл с безопасным именем `paper-cat-world-YYYY-MM-DD.json`; дата формируется UI и не попадает в world.
- Импорт использует file picker для `.json`, читает во временную переменную и заменяет `WorldStore` только после успешного `loadWorld`. При отказе текущий мир, выбор и history остаются нетронутыми.
- После успешной команды приложение сериализует world в localStorage с debounce 500 мс. На `pagehide` оно синхронно записывает последнюю уже подготовленную строку, не выполняя тяжёлый render.
- Ключ автосохранения — `paper-cat-world:autosave:v1`. Ошибка quota/storage показывает предупреждение, но не прерывает игру и не заменяет явный экспорт.
- При старте валидное автосохранение вызывает диалог «Восстановить / Начать новый мир». Повреждённое сохраняется до явного удаления пользователем для диагностики, но не загружается и сопровождается понятным сообщением.
- После import/restore создаётся новая пустая history с загруженным world; действия предыдущей сессии отменить нельзя.

## Производительность и адаптивность

- Drawing texture cache ограничивается бюджетом из UI config и освобождает least-recently-used невидимые текстуры. Источник истины остаётся в strokes; любой cache miss восстанавливается без изменения world.
- После завершения stroke перестраивается только изменившийся drawing. Во время жеста рисуется отдельный preview layer.
- Renderer выполняет culling по мировому AABB относительно viewport с запасом. Вложенная ветвь не обходится для рендера, если невидим или полностью вне viewport её host; открытые объекты внутри видимой области не пропадают.
- Для дальнего zoom используются уменьшенные версии drawing cache, но hit testing и модель продолжают работать в исходной геометрии.
- Добавить debug-счётчики только для development: число display objects, texture cache size, cache rebuilds и frame time sample. Они не входят в сохранение и выключены в production.
- Мобильный layout располагает основные действия в нижней панели, редактор — в полноэкранном режиме. Все targets не меньше 44×44 CSS-пикселя, интерфейс учитывает safe-area и не опирается на hover.
- Ошибки команд показываются кратким toast/inline-сообщением с локализованным текстом; технический `error.code` доступен в development console.

## Последовательность реализации

1. Зафиксировать schema v1 и явные структурные валидаторы envelope/world. Повторно использовать доменную `validateWorld`, не поддерживать частично валидные состояния.
2. Реализовать стабильный `serializeWorld`, `loadWorld` и registry последовательных pure migrations. Добавить ограничения на размер файла/количество данных в UI до передачи в renderer.
3. Реализовать export/import UI, безопасное имя файла, атомарную замену store и сброс history после успеха.
4. Реализовать autosave service с debounce, обработкой storage ошибок и стартовым restore-dialog.
5. Создать общую E2E fixture/utility для рисования strokes, drag, touch и сравнения сериализованного состояния.
6. Реализовать texture LRU, culling и дальний cache level; убедиться, что оптимизация не меняет hit testing, visibility и JSON.
7. Довести responsive layout для desktop/tablet/phone, safe-area, focus order, keyboard actions и минимальные touch-targets.
8. Автоматизировать максимально детерминированные части восьми приёмочных сценариев в Chromium и mobile-webkit.
9. Провести ручной Firefox smoke-test и реальный touch/stylus smoke-test, зафиксировать результаты в pull request/release checklist, а не в runtime-коде.
10. Выполнить production build и полный vertical-slice walkthrough из чистого localStorage.

## Ошибки и крайние случаи

Новые коды: `INVALID_JSON`, `INVALID_FORMAT`, `INVALID_SCHEMA_VERSION`, `UNSUPPORTED_SCHEMA_VERSION`, `MIGRATION_FAILED`, `INVALID_SAVE`, `MISSING_TEMPLATE`. UI отдельно обрабатывает `FILE_TOO_LARGE`, `FILE_READ_FAILED`, `STORAGE_UNAVAILABLE`, `STORAGE_QUOTA_EXCEEDED`.

- Пустой файл, массив вместо объекта, неизвестный format и future schema не изменяют текущий мир.
- JSON с валидной структурой, но циклом, dangling ID, `NaN`-подобным нечисловым значением или неверной зоной отклоняется целиком.
- Повторный импорт одного файла даёт структурно равный world и одинаковую визуальную сцену.
- localStorage может быть недоступен в private mode; явный экспорт продолжает работать.
- Закрытие вкладки во время debounce не должно записать предыдущую версию вместо уже подготовленного последнего snapshot.
- Culling не влияет на экспорт и не удаляет Pixi objects так, чтобы потерять selection/interaction после возвращения камеры.
- При максимальном отдалении весь стол и содержимое всех открытых видимых поверхностей отображаются хотя бы в низком LOD.
- Большой, но допустимый drawing восстанавливается постепенно без блокировки ввода дольше одного кадра там, где работу можно разбить; канонический world доступен сразу.

## Автоматические тесты

Vitest (`npm test`):

- serialize → load → serialize даёт глубоко равный envelope с отсортированными ID;
- все сущности, drawings, surfaces, attachments, open states и active spreads переживают round-trip;
- history/UI/cache отсутствуют в JSON;
- parse, format, current/future version и migration registry дают стабильные результаты;
- каждый инвариант раздела 10 отклоняется как `INVALID_SAVE` с детальным path;
- отсутствующий template config даёт `MISSING_TEMPLATE`;
- autosave debounce выбирает последнее успешное состояние и корректно обрабатывает storage exceptions;
- LRU освобождает кэш, после чего drawing восстанавливается из strokes;
- culling bounds учитывает camera zoom и вложенные world matrices.

Playwright (`npm run test:e2e`):

1. Создать двух разных котов, экспортировать/импортировать и сравнить визуальный snapshot плюс доменные данные.
2. Переносить широкую шляпу между котами и проверить неизменное выравнивание/отсутствие clipping.
3. Создать стул, положить в разворот и переместить тетрадь вместе с ним.
4. Перевезти котов в закрытом sheet между тетрадями.
5. Переместить вложенные sheet с котом без потери ссылок после JSON round-trip.
6. Отклонить цикл и проверить возврат preview и неизменный serialized world.
7. В mobile-webkit рисовать одним pointer, pinch двумя и drag object без hover.
8. Fit-to-table показывает все открытые комнаты/листы; culling не скрывает объекты внутри viewport.

Дополнительные E2E:

- повреждённый import сохраняет текущую сцену;
- reload предлагает валидное автосохранение, restore восстанавливает мир, отказ начинает чистый;
- production preview не показывает debug-панель;
- измерение DOM targets подтверждает минимум 44×44 CSS-пикселя.

## Ручное демо и браузерная матрица

1. Очистить localStorage, выполнить `npm test`, `npm run test:e2e` и `npm run build`.
2. В Chromium пройти вертикальный срез: кот, одежда, предмет, sheet, notebook, вложенность, экспорт/import.
3. Повредить копию JSON и убедиться, что import не заменяет открытый мир.
4. Перезагрузить страницу, восстановить autosave и проверить, что undo-history пуста.
5. В WebKit на touch-устройстве/эмуляции повторить drawing, pinch, drag и перевозку кота.
6. В актуальном Firefox вручную проверить запуск, pan/zoom, drawing, attach, sheet/notebook и JSON round-trip; некритичные различия анимации допустимы, потеря функций — нет.
7. Сильно отдалить камеру и проверить весь стол с открытыми поверхностями, затем приблизить обратно без пропажи объектов/рисунков.

## Checklist готовности

- [ ] JSON v1 самодостаточен для пользовательского мира и стабилен при round-trip.
- [ ] Любая ошибка import оставляет текущий мир неизменным.
- [ ] Autosave помогает восстановлению, но не заменяет явный экспорт.
- [ ] History, UI-state и рендерные кэши не сериализуются.
- [ ] Culling/LOD не меняют модель, видимость и hit testing в viewport.
- [ ] Все интерактивные targets соответствуют минимуму 44×44 и работают без hover.
- [ ] Все восемь сценариев проходят в обязательных Playwright-проектах.
- [ ] Firefox и реальное touch/stylus управление прошли ручной smoke-test.
- [ ] Production build работает без сервера и аккаунта в границах PoC.
