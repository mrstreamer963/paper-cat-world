# Этап 5. Листы и тетради

## Цель и результат

Добавить универсальные складываемые листы и тетради-дома как доменные контейнеры. Открытие управляет доступностью поверхностей, но не уничтожает содержимое. Рекурсивная вложенность обычных листов должна выражать чемоданы, машины и «многоэтажную машину» без специальных классов.

Запускаемый результат — котов можно посадить во внутреннюю поверхность листа, закрыть его, перенести к тетради, открыть и высадить в выбранную комнату. Один лист можно вложить в другой и перемещать всё дерево без потери связей.

## Зависимости и границы

Этап начинается после полного checklist [этапа 4](04-cats-and-clothing.md). Он расширяет уже существующие сущности/поверхности, visibility query, renderer и команды истории.

В PoC лист сгибается только пополам по фиксированной центральной линии. Не входят переворот для показа нижней стороны, произвольные сгибы, физическая толщина, столкновения, вес, специальные сиденья машины и отдельный экран комнаты.

## Модель листа

Sheet-сущность имеет `kind: "sheet"`, `state: "open" | "closed"` и ссылки:

```js
{
  insideSurfaceId,
  outerTopSurfaceId,
  outerBottomSurfaceId
}
```

Каждая сторона — обычная принадлежащая листу поверхность со своим `drawingId`, локальной трансформацией и `placementArea`. Роль поверхности хранится как `kind: "sheet-inside" | "sheet-outer-top" | "sheet-outer-bottom"`.

Локальная доступность выводится из состояния владельца, а не меняется отдельными командами:

- `open`: видима и интерактивна только внутренняя поверхность;
- `closed`: видима и интерактивна только верхняя наружная поверхность;
- нижняя наружная поверхность хранит рисунок и содержимое, но в PoC всегда скрыта на столе.

`setSurfaceVisibility` этапа 1 остаётся только для `generic` fixture-поверхностей и не принимает доменные поверхности sheet/notebook.

`createSheet` получает все ID сущности, поверхностей и drawings снаружи и создаёт полный лист атомарно. `toggleSheet`/`setSheetState` разрешены только если сама sheet-сущность находится на видимой поверхности. Закрытие не проверяет «толщину» и не перемещает содержимое.

## Модель тетради

Notebook-сущность имеет `kind: "notebook"`, `state`, `coverSurfaceId`, `activeSpreadIndex` и массив `spreads`:

```js
{
  id: "spread-1",
  surfaceId,
  drawingId
}
```

Разворот — одна логическая поверхность, визуально разделённая сгибом на две страницы. Число разворотов находится в данных создания; стартовая fixture содержит три. При `closed` видна только cover surface, при `open` — только surface активного разворота. Неактивные комнаты остаются в world, но невидимы и неинтерактивны.

Команды `createNotebook`, `setNotebookState` и `setActiveSpread` атомарны и участвуют в истории. Перелистывание допустимо только для открытой видимой тетради и индекса в диапазоне. Закрытая тетрадь сохраняет `activeSpreadIndex` для следующего открытия.

## Представление и анимации

- Renderer строит ветви всех поверхностей один раз, а visibility query определяет, какая роль участвует в display/hit testing.
- `sheetStateChanged`, `notebookStateChanged` и `activeSpreadChanged` содержат предыдущие/новые значения, достаточные для визуальной интерполяции.
- Сгиб/раскрытие — короткая renderer-анимация. На время анимации конкретный host блокирует повторное действие; world уже находится в конечном состоянии.
- Перелистывание использует простой сдвиг/затухание без физической симуляции страницы.
- Double tap по sheet переключает состояние. То же действие всегда доступно кнопкой выбранного объекта. Для notebook кнопки открывают/закрывают и переключают развороты; double tap обложки только открывает.
- Drag target candidates включают только поверхности, которые видимы и интерактивны в конечном canonical state.

## Последовательность реализации

1. Расширить модель поверхностей опциональным `drawingId` и role-kind; проверить существование drawing и совместимость role с host entity.
2. Добавить sheet/notebook data validators и вычисление локальной видимости по виду владельца. Сохранить единый рекурсивный запрос этапа 1 для всей ветви.
3. Реализовать атомарные create/state/spread команды, события и inverse history operations.
4. Создать редактор сторон листа: внутренняя, верхняя и нижняя вкладки используют общий drawing editor. Нижнюю сторону можно редактировать в диалоге, хотя на столе она не отображается.
5. Реализовать создание sheet с фиксированными размерами/линией сгиба из config и начальным рисунком каждой стороны.
6. Реализовать notebook fixture/создание из data с обложкой и тремя разворотами; комнаты используют существующие поверхности и принимают любые обычные сущности.
7. Обновить display tree, hit testing и target selection для role visibility. Невидимые ветви не уничтожать и не отдавать контроллерам.
8. Добавить UI-действия, double tap recognizer и блокировку повторного toggle на время анимации. Обычный single tap должен оставаться выбором и не срабатывать преждевременно.
9. Реализовать fold/page animations как реакцию на core events без записи промежуточного состояния в world.
10. Добавить fixture вертикального среза: две тетради, sheet-машина, вложенный sheet и созданные ранее коты/детали.

## Ошибки и крайние случаи

Новые коды: `NOT_A_SHEET`, `NOT_A_NOTEBOOK`, `INVALID_SHEET`, `INVALID_NOTEBOOK`, `INVALID_SPREAD_INDEX`, `SURFACE_ROLE_MISMATCH`, `HOST_NOT_VISIBLE`, `ACTION_IN_PROGRESS` (только UI, не core).

- Sheet, лежащий внутри закрытого sheet или неактивной комнаты, нельзя открыть через команду взаимодействия.
- Закрытие внешнего sheet немедленно скрывает всё дерево, включая открытый внутренний sheet; состояния потомков не меняются.
- После повторного открытия внешний sheet показывает внутренний sheet в прежнем `open/closed` состоянии.
- Циклическое вложение по-прежнему отклоняет общий `moveEntity`; отдельной логики для «многоэтажной машины» нет.
- Предметы на outer-top скрываются при открытии, но не перемещаются и появляются после закрытия.
- Undo закрытия/перелистывания восстанавливает видимость и доступность соответствующей ветви.
- Попытка выбрать отсутствующий spread не изменяет активную комнату.
- Double tap не должен одновременно завершать drag или вызывать два toggle.

## Автоматические тесты

Vitest (`npm test`):

- полная валидация sheet surface roles, drawings и уникальности ссылок;
- visibility matrix для всех сторон sheet в open/closed;
- закрытие внешнего sheet скрывает открытые и закрытые ветви любой глубины, не меняя данные потомков;
- nested sheet move сохраняет мировые позы всего дерева;
- создание notebook с конфигурируемым числом spreads;
- visibility cover/active/inactive spreads для open/closed;
- setActiveSpread: успех, границы, скрытый host и undo/redo;
- цикл с двумя sheet отклоняется существующим `CYCLE_DETECTED`;
- drawings и сущности скрытых поверхностей сохраняются без изменений.

Playwright (`npm run test:e2e`):

- открыть sheet, посадить котов, закрыть и убедиться, что hit testing их не находит;
- перенести закрытый sheet, открыть и высадить котов;
- вложить один sheet в другой, закрыть внешний и перенести дерево;
- открыть/закрыть notebook, переключить три spreads и сохранить мебель в каждой комнате;
- переместить notebook и убедиться, что мебель активной комнаты движется вместе с ним;
- double tap и DOM-кнопки не конфликтуют с drag;
- mobile-webkit проходит перевозку кота только touch-действиями.

## Ручное демо

1. Выполнить `npm test`, `npm run test:e2e` и `npm run build`.
2. Положить нарисованный стул в первый разворот тетради, переместить тетрадь и проверить совместное движение.
3. Открыть sheet-машину, посадить двух котов, закрыть и перенести к другой тетради.
4. Открыть машину, открыть нужный разворот и высадить котов в комнату.
5. Положить открывающийся sheet с котом внутрь другого sheet, закрыть внешний и переместить конструкцию.
6. Попытаться положить внешний sheet в потомка и увидеть возврат preview без потери связей.

## Checklist готовности

- [ ] Sheet и notebook выражены обычными сущностями и принадлежащими поверхностями.
- [ ] Видимость выводится из state/role и рекурсивно применяется к содержимому.
- [ ] Скрытые ветви сохраняются, но отсутствуют в hit testing и target candidates.
- [ ] Вложенность листов не использует специальную сущность машины.
- [ ] Анимации не добавляют промежуточные состояния в core.
- [ ] Сценарий перевозки между тетрадями проходит мышью и touch.
