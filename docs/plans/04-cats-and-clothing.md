# Этап 4. Коты и одежда

## Цель и результат

Реализовать основную фантазию бумажной куклы: пользователь раскрашивает канонический силуэт и получает кота, затем рисует выступающую за силуэт одежду и автоматически прикрепляет её к любому совместимому коту. Поза одежды восстанавливается из координат шаблона, а не из места отпускания.

Запускаемый результат — два по-разному раскрашенных кота и одна шляпа шире головы. Шляпу можно по очереди надеть на обоих котов; она одинаково выравнивается, не обрезается силуэтом и перемещается/вращается/масштабируется вместе с хозяином.

## Зависимости и границы

Этап начинается после полного checklist [этапа 3](03-drawing-and-cutting.md). Он переиспользует редактор strokes, scissors, cutout, вложенные поверхности и историю команд.

В PoC одна каноническая поза кота. Не входят анимация тела, разные пропорции/позы, ручная корректировка зоны после вырезания, деформация одежды, гардероб-каталог и семантика предметов.

## Шаблон и модель

Шаблон кота — версионированный asset с `templateId`, `viewBox`, замкнутым силуэтом и именованными зонами `head`, `face`, `body`, `paws`, `back`. SVG использует только `<polygon>` для силуэта и зон: зоны могут состоять из нескольких элементов с одинаковым `data-zone`. При загрузке приложение читает атрибут `points`, создаёт plain polygon data и передаёт его через `createWorld({ ..., templates })`. Нормализованный реестр доступен командам как `world.rules.templates`; core не читает SVG и не зависит от DOM.

Каждая зона задаёт один или несколько выпуклых полигонов, `layer` и `tiePriority`. Порядок зон и слоёв находится в данных шаблона. Валидация config отклоняет неизвестные/пустые зоны до создания мира.

Cat-сущность имеет:

```js
{
  kind: "cat",
  templateId,
  drawingId,
  attachmentSurfaceId,
  ...commonEntityFields
}
```

Её drawing хранится в канонических координатах и отображается через маску силуэта. При создании кот получает принадлежащую ему поверхность `kind: "cat-attachments"` с единичной трансформацией в тех же координатах шаблона.

Wearable остаётся обычной cutout-сущностью и дополнительно содержит:

```js
{
  wearable: {
    templateId,
    zoneId,
    templateTransform: { x, y, rotation, scale }
  },
  attachment: null | { catId, zoneId }
}
```

`templateTransform` фиксируется при вырезании и не меняется при attach/detach. Контур wearable не маскируется зоной или силуэтом кота.

## Команды и правила привязки

- `createCat` получает заранее созданные `catId`, `drawingId`, `attachmentSurfaceId`, `templateId`, целевую поверхность и мировую трансформацию. Drawing создаётся/заполняется обычными командами редактора; подтверждение атомарно создаёт cat и его attachment surface.
- `createWearableCutout` расширяет `createCutout`: получает contour в координатах шаблона, вычисляет зону, сохраняет template transform и создаёт свободную деталь рядом с редактором.
- `attachWearable` получает `wearableId` и `catId`. Core проверяет template compatibility, видимость обоих объектов и наличие зоны, затем переносит wearable на attachment surface кота и устанавливает ровно `templateTransform`.
- `detachWearable` переносит wearable на явно переданную видимую поверхность рядом с котом с сохранением текущей мировой позы и очищает `attachment`; wearable-метаданные остаются.

Обычная `moveEntity` для прикреплённой одежды возвращает `ENTITY_ATTACHED`; сначала требуется detach. При attach renderer может показывать snap-анимацию от места отпускания к канонической позе, но world сразу содержит конечную привязку.

Зона выбирается максимальной суммарной площадью пересечения contour wearable с полигонами зоны в template-space. Если максимальная площадь нулевая, создание отклоняется. Равенство в пределах epsilon разрешается наименьшим `tiePriority`, затем лексикографически по `zoneId`.

На attachment surface сортировка выполняется по `(zone.layer, entity.zIndex, entity.id)`. `bringEntityToFront` для прикреплённой одежды поднимает её только внутри той же зоны, не меняя layer зоны. Тело кота визуально находится между отрицательными и неотрицательными zone layers; конкретные значения задаёт шаблон.

## Последовательность реализации

1. Добавить SVG-шаблон кота с каноническим `viewBox`, размеченными `<polygon>` и loader, преобразующий их `points` в plain polygon config до создания мира.
2. Расширить конфигурацию и валидацию core реестром templates, зонами, layer и tiePriority. Добавить polygon clipping/area для пересечения произвольного contour с выпуклыми зонами.
3. Добавить cat и cat-attachments в модель, проверяя template/drawing/surface ссылки и запрет вложения посторонних сущностей на attachment surface.
4. Реализовать отдельный режим «Новый кот»: фиксированный силуэт под/над drawing, brush/eraser, подтверждение без scissors и отмена без частичного cat.
5. Реализовать режим «Новая одежда»: расширенный холст вокруг видимого силуэта, существующие инструменты drawing/scissors и создание wearable в координатах шаблона.
6. Реализовать `createCat`, `createWearableCutout`, `attachWearable`, `detachWearable` и их inverse history operations.
7. Расширить drag target selection: при отпускании wearable над видимым cat сначала пробовать attach, а при отказе — обычное размещение на подходящей поверхности.
8. Добавить renderer для маски тела кота и отдельный attachment container без общей cat mask. Реализовать zone layering и snap-анимацию по событиям.
9. Добавить DOM-действие «Снять» для выбранной прикреплённой одежды; место снятия рассчитывает контроллер и передаёт как явную мировую позу.

## Ошибки и крайние случаи

Новые коды: `TEMPLATE_NOT_FOUND`, `INVALID_TEMPLATE`, `INCOMPATIBLE_TEMPLATE`, `WEARABLE_ZONE_NOT_FOUND`, `NOT_WEARABLE`, `NOT_A_CAT`, `ALREADY_ATTACHED`, `ENTITY_ATTACHED`, `INVALID_ATTACHMENT`.

- Clothing contour может полностью выходить за силуэт, но обязан пересекать хотя бы одну зону.
- Пересечение с несколькими зонами всегда даёт один детерминированный `zoneId`.
- Attach к скрытому или находящемуся в скрытой ветви коту отклоняется.
- Повторный attach к тому же коту возвращает `ALREADY_ATTACHED` без history entry.
- Attach к другому коту требует сначала detach; drag-controller может оформить detach + attach одной составной history operation.
- Удаление кота с прикреплёнными деталями отклоняется как непустой контейнер. Пользователь сначала снимает одежду.
- Undo/redo attach восстанавливает исходную поверхность, трансформацию, `zIndex` и attachment metadata.
- Шляпа, крылья и другие выступающие части обрезаются только собственным cutout contour, никогда cat silhouette.

## Автоматические тесты

Vitest (`npm test`):

- загрузка валидного template config и отказ для отсутствующих зон/невалидных полигонов;
- площадь пересечения concave clothing contour с каждой convex-зоной;
- детерминированный выбор зоны, включая tiePriority;
- `createCat` атомарно создаёт cat и attachment surface;
- attach устанавливает точный template transform для двух котов с разными мировыми позами;
- attached wearable наследует translate/rotate/scale кота;
- detach сохраняет мировую позу и wearable binding;
- запрет обычного move и удаления host-кота при attachment;
- undo/redo create, attach, detach и составного переноса между котами;
- validateWorld обнаруживает несовместимый template, неизвестную зону и рассинхронизацию `attachment.catId`/surface owner.

Playwright (`npm run test:e2e`):

- создать двух котов с визуально различными strokes;
- нарисовать шляпу шире головы и вырезать её;
- drag на первого кота запускает snap и не обрезает поля шляпы;
- перемещение/поворот кота переносит шляпу вместе с ним;
- снять и надеть на второго кота с тем же выравниванием;
- undo/redo переноса между котами;
- mobile-webkit выполняет создание и attach без hover.

## Ручное демо

1. Выполнить `npm test`, `npm run test:e2e` и `npm run build`.
2. Создать двух котов, раскрасив их по-разному.
3. В расширенном редакторе нарисовать шляпу, заметно выступающую за голову, и вырезать её.
4. Надеть шляпу на первого кота, повернуть и переместить кота.
5. Снять шляпу и надеть на второго кота; сравнить положение относительно шаблона.
6. Отменить и повторить перенос; проверить отсутствие обрезания по силуэту.

## Checklist готовности

- [ ] Все коты используют одну каноническую систему координат.
- [ ] Зона и template transform определяются и сохраняются детерминированно.
- [ ] Attachment выражен доменными ссылками и проверяется `validateWorld`.
- [ ] Одежда наследует трансформацию кота и не обрезается его маской.
- [ ] Attach/detach полностью участвуют в undo/redo.
- [ ] Сценарий одной шляпы на двух котах проходит в обоих Playwright-проектах.
