# Этап 2. Стол и манипуляция

## Цель и результат

Построить браузерное представление мира этапа 1 и преобразовать мышь, стилус и touch-жесты в атомарные команды ядра. Пользователь видит большой стол, двигает камеру, выбирает, перетаскивает и поворачивает тестовые бумажные прямоугольники, включая перенос на поверхности других прямоугольников.

Запускаемый результат — `npm run dev`: стартовая fixture-сцена содержит стол, несколько деталей и два generic-контейнера. Объекты можно разложить и вложить, не редактируя состояние через DevTools.

## Зависимости и границы

Этап начинается после полного checklist [этапа 1](01-geometric-core.md). Он добавляет Vite, PixiJS, HTML/CSS UI, Playwright и каталоги приложения/рендеринга.

Рисование, вырезание, коты, доменные листы/тетради, сохранение и сложные анимации не входят. Все сущности пока отображаются цветными прямоугольниками; generic-поверхности видимы как пунктирные области.

## Интерфейсы приложения и рендера

Приложение хранит отдельное состояние интерфейса:

```js
{
  selectedEntityId: null | string,
  interaction: { mode, pointerIds, dragPreview },
  camera: { x, y, zoom }
}
```

`WorldStore` владеет текущим `world`, вызывает только `applyCommand`, публикует успешные `{ world, events }` и не уведомляет подписчиков при отказе. Ошибка передаётся UI для короткой подсказки.

`PixiWorldRenderer` принимает снимок мира и UI-state, поддерживает отображение по стабильным ID и не хранит канонические координаты. Он предоставляет контроллеру:

- `screenToWorld(point)` и `worldToScreen(point)` с учётом камеры;
- `hitTest(screenPoint)` — упорядоченный список видимых кандидатов сверху вниз;
- `getSurfaceCandidates(screenPoint)` — видимые поверхности под точкой, от наиболее глубокой/верхней к столу;
- `render(world, uiState, events)` — синхронизацию display tree.

Контроллер при отпускании выбирает первую поверхность-кандидат, в которую попадает anchor point и для которой пробная команда ядра успешна. Если все цели отклонены, sprite анимируется к исходной позе, а мир не меняется.

## Жесты и правила приоритета

- Tap одним указателем выбирает верхнюю интерактивную сущность; tap по пустому месту снимает выбор.
- Drag сущности одним указателем двигает только preview. На `pointerup` отправляется одна `moveEntityInWorld` с `zPolicy: "front"`; перенос и подъём слоя происходят атомарно в этой команде.
- Drag пустого места двигает камеру. Мышью камеру также двигают средней кнопкой или `Space + drag` независимо от начала жеста.
- Колесо масштабирует относительно позиции курсора. Два активных touch-указателя всегда отменяют потенциальный object drag и управляют pan/zoom камеры вокруг midpoint.
- Поворот выполняется кнопками выбранного объекта с фиксированным шагом, заданным конфигурацией UI. Для touch это доступная кнопка 44×44 CSS-пикселя; hover не требуется.
- Кнопка «Показать весь стол» вписывает границы стола во viewport с отступом. Zoom ограничен конфигом, а камера не допускает полной потери стола за экраном.
- На canvas применяется `touch-action: none`; системные жесты вне canvas не блокируются.

## Последовательность реализации

1. Добавить Vite, PixiJS и Playwright; создать `index.html`, точку входа и адаптивный полноэкранный layout с canvas и DOM-панелью выбранного объекта.
2. Создать fixture-фабрику через команды ядра. В production/dev-коде не собирать мир прямой записью в словари.
3. Реализовать `WorldStore` и однонаправленный поток `input → controller → core → store → renderer`.
4. Построить Pixi display tree по чередующемуся графу поверхностей и сущностей. Для каждого ID переиспользовать display object; удалять только отсутствующие элементы.
5. Реализовать camera container, преобразования координат, fit-to-table и обработку resize/DPR без изменения мира.
6. Реализовать hit testing видимых прямоугольников и поверхностей. Кандидаты сортировать по фактическому порядку вложенности и локальному `zIndex`.
7. Реализовать pointer state machine с явными состояниями `idle`, `pending`, `drag-object`, `pan-camera`, `pinch-camera`. Обработать `pointercancel`, потерю capture и добавление второго пальца.
8. Реализовать drag-preview, выбор цели и commit одной команды на отпускании. При отказе показать ненавязчивую подсказку по `error.code` и вернуть preview.
9. Добавить DOM-действия поворота, удаления выбора из UI-state и «Показать весь стол». Удаление сущности мира остаётся вне этапа.
10. Настроить Playwright webServer и два проекта: desktop `chromium` и touch-enabled `mobile-webkit`.

## Ошибки и крайние случаи

- Удаление/скрытие выбранной сущности программной fixture-командой автоматически очищает выбор.
- Второй палец во время pending/drag не выполняет `moveEntity`; preview возвращается и начинается pinch.
- `pointercancel`, уход вкладки в background и потеря capture возвращают preview без команды.
- Drag в скрытую, внешнюю или циклическую цель показывает причину отказа и сохраняет исходную модель.
- Resize и смена DPR не меняют логическую позицию камеры и сущностей.
- Hit testing не возвращает содержимое скрытой ветви, даже если старый Pixi object ещё участвует в анимации.
- Быстрая последовательность жестов не создаёт два commit для одного `pointerup`.

## Автоматические тесты

Vitest (`npm test`):

- store применяет успех, сохраняет мир при отказе и публикует события один раз;
- pointer state machine корректно проходит drag, pan, pinch, cancel и переход ко второму пальцу;
- screen/world round-trip работает при разных camera zoom и viewport;
- выбор target surface соответствует порядку кандидатов и отказам ядра;
- renderer adapter скрывает невидимые ветви и сохраняет display objects по ID.

Playwright (`npm run test:e2e`):

- Chromium: выбрать прямоугольник, перетащить на стол и повернуть кнопкой;
- Chromium: вложить объект в generic-контейнер и переместить контейнер вместе с содержимым;
- Chromium: wheel zoom, Space-drag и «Показать весь стол»;
- mobile-webkit: tap, drag объекта, drag пустого места и pinch двумя touch points;
- оба проекта: попытка циклического вложения возвращает preview и не портит мир;
- оба проекта: основные действия доступны без hover, интерактивные DOM-элементы не меньше 44×44.

## Ручное демо

1. Выполнить `npm test`, `npm run test:e2e` и `npm run build`.
2. Запустить `npm run dev`, открыть сцену сначала в desktop, затем в touch-emulation браузера.
3. Переместить и повернуть деталь, положить её во внутреннюю область контейнера и перенести контейнер.
4. Вложить один контейнер в другой и проверить, что вся ветвь движется единым целым.
5. Попытаться положить внешний контейнер внутрь внутреннего: preview должен вернуться, мир — остаться валидным.
6. Проверить pan/zoom и возврат к полному столу.
